# Documentation Template

Use this structure. Omit a section only if it genuinely doesn't apply, and say so.

```
# [Component Group Name]
Source: [link] · Documented: [date]

## Group overview
- What this set covers (list components)
- Shared conventions (sizing scale, token use, state model)
- Gaps or inconsistencies noticed across the set

---

## [Component Name]

### Overview
One or two sentences: what it is and the problem it solves.

**Use when**
- ...
**Don't use when** (and what to use instead)
- ...

### Anatomy
Numbered list of parts (container, label, icon, etc.)

### Variations
| Variant | Values | Purpose | Choose it when |
|---|---|---|---|

### Properties
| Property | Type | Values | Default | Effect |
|---|---|---|---|---|

### States
Table of states present. List expected states that are missing.

### Usage guidelines
Placement, sizing, spacing, content rules, composition with other components.

### Dos and don'ts
| Do | Don't |
|---|---|

### Accessibility
**Observed in the file**
- ...
**Recommended**
- ...

---

## Open questions
Items that couldn't be determined from the file.
```
